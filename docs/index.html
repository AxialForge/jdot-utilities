What it does

One app for the file chores that usually send you to an upload-your-file website — all of it local.

  • Convert documents — Markdown, HTML, Word (.docx), text, PDF
  • Convert images — PNG, JPG, WebP, AVIF, TIFF, GIF, BMP, HEIC, and Windows ICO
  • Convert data — JSON, YAML, CSV, TSV, XML
  • Office to PDF — Word, spreadsheets, presentations (via LibreOffice)
  • Merge, split, rotate, delete and extract PDF pages
  • Images to PDF, and PDF to images
  • PDF to text, and OCR for scanned PDFs (offline)
  • Shrink and compress PDFs; convert to archival PDF/A
  • Watermark PDFs and edit their document info

Runs offline

No server, no localhost, no upload step. Install the app and convert — airplane mode works fine. It only touches the network if you press Check for updates.

No account

No sign-up, no history database. Open it and go straight to work.

Built to extend

Every tool is one self-describing file. Drop it in and the app renders the interface for it automatically.

Code signing

These builds are not code-signed yet. Windows SmartScreen may warn on first run — choose More info, then Run anyway. Signing is being set up through the SignPath Foundation open-source program; the policy below is how it will work once it's live.

Attribution

Once active: free code signing provided by SignPath.io, certificate by SignPath Foundation.

How builds are produced

Every release is built from public source by GitHub Actions when a version tag is pushed (see .github/workflows/build.yml). The build sets the product name and version as signed metadata. Signing is requested only for tagged releases, and each signing request is approved manually before the signed build is published.

Team roles

Author, committer and reviewer: AxialForge (Joseph Costarella) — the sole maintainer, who writes and reviews all changes.

Release & signing approver: AxialForge — approves each release tag and each signing request.

Privacy policy

This program will not transfer any information to other networked systems unless specifically requested by the user. The only such action is the optional, manual Check for updates in Settings, which contacts GitHub to look for a newer release; nothing downloads or installs without a further explicit action. There is no telemetry, no analytics and no account.

Adding a tool is one file

The interface is generated from the tool registry — the tool rail, output formats, and option fields all come from what a tool exports. There's nothing else to wire up.

// src/tools/data-convert.js
module.exports = {
  id: "data-convert",
  name: "Data Converter",
  category: "Data",
  inputFormats: ["json", "yaml", "csv"],
  outputFormats: ["json", "yaml", "csv"],
  async convert({ inputPath, outputPath, outputFormat }) {
    /* read, transform, write — pure JS or a bundled binary */
  },
};
